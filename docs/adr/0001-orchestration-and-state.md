# ADR 0001 · 工作流底座与持久化状态

**状态** 拟议 · 2026-11-27

## 决策建议

在 Phase 0 优先试用 Archon 的公开 Provider 插件、工作流和事件接口。QuotaFlow 拥有额度与预算租约、工作区写入权和跨 Agent 检查点。若采用 Archon，其运行器负责工作流节点的生命周期，QuotaFlow 以关联 ID 保存调度、执行尝试及检查点，并向操作界面投影工作流状态。每项状态由唯一责任组件写入。

采用轻量独立核心时，用 TypeScript、Bun 和单机 SQLite 保存队列、节点状态、写入意图及事件。先交付可恢复的最小流程，再扩展声明式工作流。Agent 与 GitHub 接入通过端口隔离，Phase 0 的契约及故障注入测试可在两种路径复用。

## 选型条件

- 自定义 Provider 插件或公开委托接口能在任务边界交由 QuotaFlow 调度和取消，并提供可关联的结构化事件。
- Archon 重启或节点重试后，QuotaFlow 能从同一个任务检查点恢复，工作区写入者始终唯一。任务等待额度时，其他任务可继续，重放能定位到明确的工作流版本与节点。
- GitHub、Worktree 和 Dashboard 可通过公开契约组合；独立 Reviewer 与高风险审批能在外部写入前施加约束。
- 锁定运行版本后，升级成本可用适配器契约测试控制，复用方式符合上游和三方许可证。

关键条件失败时，复跑同一用例评估独立路径。固定失败证据和迁移成本，再定版此 ADR。备选 Symphony 提供工作区及轮询恢复参考，Ralph Workflow、Hats、MetaSwarm、AgentBridge 和 Beads 按经验证的能力独立评估复用。[源码初筛](../RESEARCH.md)
