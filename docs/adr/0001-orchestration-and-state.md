# ADR 0001 · 工作流底座与持久化状态

**状态** 暂定建议；Phase 0 技术门禁有条件通过，Phase 1 已启动，剩余验收项待复核 · 2026-11-27

## 决策

Phase 1 原型建议采用轻量独立核心。TypeScript、Bun 和单机 SQLite 管理队列、写租约、检查点意图及事件。额度与工作区写入权由同一个事务边界发放。Git 私有引用提供恢复时可对账的代码检查点。初始工作流从可恢复的最小流程扩展，Agent 与 GitHub 通过适配接口接入。该决定仍属暂定：真实 Codex Agent 写入和跨 Agent 恢复已取得阶段门禁通过证据，Phase 1 已启动，剩余验收项待负责人复核。

Archon v0.16.0 实测可以在独立 Worktree 保存失败状态，恢复时跳过已完成节点。采用它作为主运行器还需验证由公开委托接口控制任务级额度租约、跨 Agent 进程停止以及 Git 检查点。当前独立切片已覆盖这些职责，首版可保持运行状态归属清晰。Archon 继续作为工作流、事件与 GitHub 集成的参考。[运行对照](../PHASE-0.md)

## 重新评估条件

- 自定义 Provider 插件或公开委托接口能在任务边界交由 QuotaFlow 调度和取消，并提供可关联的结构化事件。
- Archon 重启或节点重试后，QuotaFlow 能从同一个任务检查点恢复，工作区写入者始终唯一。任务等待额度时，其他任务可继续，重放能定位到明确的工作流版本与节点。
- GitHub、Worktree 和 Dashboard 可通过公开契约组合；独立 Reviewer 与高风险审批能在外部写入前施加约束。
- 锁定运行版本后，升级成本可用适配器契约测试控制，复用方式符合上游和三方许可证。

未来如可通过公开接口满足这些条件，可复用 Phase 0 契约测试再评估 Archon。Symphony 提供工作区及轮询恢复参考，Ralph Workflow、Hats、MetaSwarm、AgentBridge 和 Beads 按具体能力评估复用。[源码初筛](../RESEARCH.md)
