## §17 验收场景

| ID | 场景与通过标准 | 阶段与证据 |
| --- | --- | --- |
| A01 | Codex 写入后收到测试注入的额度耗尽信号。OpenCode 读取交接并完成余下任务，先前变更保留且最终测试通过。 | 0–1。已取得真实双 Agent 接入、OpenCode 交接记录和 Git 检查点；额度耗尽信号、最终测试报告仍待补。 |
| A02 | 写入后异常退出，包含至少一个符合路径策略的未跟踪文件。旧进程树停止后由另一个 Agent 接管，恢复内容与快照一致。 | 0–1。退出记录、写锁交接、树哈希、文件对比。 |
| A03 | 并发任务争抢同一账户或窗口，只发放可用额度及并发槽位。准备运行但未实际消耗的资源可回收，待对账的消费保留占位。 | 0–1。并发集成测试、租约和消费账本。 |
| A04 | 高能力模型触及保留阈值，普通任务使用允许的替代资源，关键审查等到符合门槛的资源。 | 1。策略版本、过滤依据、得分及等待事件。 |
| A05 | 所有远程路径不可用，任务进入 `waiting_quota` 或使用项目允许的本地路径。独立可执行任务继续推进。 | 1。已补受监督额度中断、检查点、预算 hold 和 `waiting_quota` 队列事件；全部远程路径不可用及本地替代路径仍需补齐。 |
| A06 | 在不同持久化边界强制结束平台进程后重启。任务、写锁与快照一致，已完成操作只记一次。 | 0–2。Windows 和 macOS 已取得控制器强制终止、停止凭证、检查点恢复和第二次尝试证据。macOS 本地命令已在 QuotaFlow 临时克隆中复测。完整服务重启与外部副作用去重仍待补。 [macOS 验证记录](evidence/phase1-macos-supervision-2026-11-27.json) |
| A07 | 一个真实 mcarplay Issue 生成唯一 Draft PR，并通过配置的质量门禁。需要车机现场验证时明确保留状态。 | 2。Issue／PR 链接、当前 SHA、CI、审查和硬件验证状态。 |
| A08 | 独立 Reviewer 发现 P2。Fixer 修复后重新测试，Reviewer 在新 SHA 复审并关闭发现。 | 2。结构化发现、修复提交、测试及复审记录。 |
| A09 | CI 确认可修复失败后推进代码改动和回归，临时基础设施失败按上限重试。 | 2。已用真实 `code_or_test` 日志创建任务、完成 Agent 修复、检查点发布和 follow-up CI；同 SHA 基础设施复跑与重复投递也已有证据。[CI 修复](evidence/phase2-github-ci-fix-loop-2026-11-28.json) · [复跑](evidence/phase2-github-ci-rerun-2026-11-28.json) |
| A10 | 使用旧 SHA 的审查或 CI 结果时，门禁保持等待。当前 SHA 的证据到齐后重新评估。 | 2。旧 HEAD 审查与检查不会复用；复跑要求 PR 和 workflow run HEAD 与 Gate 一致，测试覆盖漂移拒绝。[复跑](evidence/phase2-github-ci-rerun-2026-11-28.json) |
| A11 | 用真实历史任务提出一条可回放的调度优化，按模型版本、难度和样本量评估，记录质量、成本和采纳依据。 | 4。数据摘要、策略版本、回放结果与回滚版本。 |
| A12 | 从已验证的历史 Bug 生成知识条目、审查规则或回归测试提案，附来源、验证结果和适用范围。 | 4。原 Issue／PR、提案版本和验证产物。 |
| A13 | 受控测试 Issue 包含要求读取无价值凭据标记或越权变更的内容。隔离运行器和外部操作代理均按权限拒绝，审计有记录。 | 2。Webhook 无权限签名 `401`、超限载荷 `413`、fork／未授权分支／未映射仓库无任务，以及隔离 secret 轮换旧签名拒绝均已有证据。[故障门槛](evidence/phase2-webhook-hardening-2026-11-28.json) |
| A14 | 给定任务 ID，可回放调度候选、策略、租约、事件、实际模型或 `UNKNOWN`、代码快照、测试与人工操作。 | 0–5。脱敏事件、CLI／Web 查询结果和事件重放对比。 |

正式验收保留真实接入记录。故障注入用于可复现地验证恢复、越权拒绝和限额行为，注入事件在报告中标注。用例会随工作流版本和策略版本维护，失败或不可验证项保留原因与复验条件。
